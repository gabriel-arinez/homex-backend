# F07.1 — DB-01: propiedad del esquema y paridad estructural

## Resultado

Django construye el esquema comercial de HOMEX desde una base PostgreSQL vacía.
Las migraciones son la fuente operativa; `homex_bd_final_v3.sql` permanece como
referencia del contrato y no se ejecuta como un segundo bootstrap.

## Entregado

- Las 24 tablas comerciales están distribuidas entre sus aplicaciones Django y
  conservan el nombre físico definido por el contrato mediante `db_table`.
- Las cuatro secuencias comerciales se crean en una migración versionada.
- Las funciones y triggers PostgreSQL de v3 se trasladaron en migraciones
  `RunSQL`, después de crear sus tablas dependientes.
- Los actores se relacionan con `settings.AUTH_USER_MODEL`.
- Los campos técnicos conservan inglés y coinciden directamente con PostgreSQL:
  `created_by_id`, `updated_by_id`, `evaluated_by_id`, `schema_version`,
  `input_hash` y demás nombres de infraestructura auditados.
- Los campos del dominio HOMEX permanecen en español. No se usa `db_column`
  para una traducción estética.
- `transiciones_estado_pedido` usa la clave primaria compuesta
  `(estado_origen_id, estado_destino_id)` sin una columna artificial `id`.
- El mapa y las diferencias intencionales están documentados en
  `docs/base_datos/mapa_sql_modelos.md`.

## Diferencias intencionales frente a v3

Las diferencias aprobadas están documentadas en el mapa de base de datos:

- actores como claves foráneas al usuario configurable;
- `modo_calculo` e `importe_negociado` para preservar totales negociados;
- estado inmutable `EMITIDO`/`ANULADO` en recibos;
- `clave_idempotencia` única en capturas.

1. crear `homex_db01_final` vacía y aplicar `migrate --noinput`;
2. ejecutar `migrate --noinput` por segunda vez: sin migraciones pendientes;
3. verificar 24 tablas y cuatro secuencias comerciales;
4. verificar la PK compuesta de transiciones;
5. verificar las columnas técnicas y las FK hacia `accounts_user`;
6. ejecutar la suite: `8 passed`;
7. ejecutar `manage.py check`, `makemigrations --check --dry-run`, Ruff y
   `git diff --check`: correctos.
