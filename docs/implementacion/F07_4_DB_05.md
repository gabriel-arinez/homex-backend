# F07.4 — DB-05: recibos, notas y documentos

## Reglas implementadas

- Un recibo nace `EMITIDO`, conserva su evidencia comercial y sólo admite la transición `EMITIDO → ANULADO`.
- PostgreSQL calcula `total`, `a_cuenta` y `saldo`; sólo los recibos emitidos participan en el acumulado.
- Un recibo emitido impide cancelar su pedido. Al anularlo deja de computar; el sistema no registra devoluciones.
- Los recibos no se eliminan y los cobros no se aceptan para pedidos cancelados.
- La nota de entrega se emite una sola vez, sólo si el pedido está `LISTO_ENTREGA`; su fecha es la fecha de emisión.
- Los renderizadores obtienen proforma, orden de trabajo, recibo y nota desde sus datos persistidos. No se crean tablas documentales adicionales.

## API

- `POST /api/v1/pedidos/{id}/emitir_recibo/`
- `POST /api/v1/recibos/{id}/anular/`
- `POST /api/v1/pedidos/{id}/emitir_nota_entrega/`
- Consultas de recibos y notas mediante los viewsets de sólo lectura.

## Validación de cierre

- Recibo correcto, sobrepago rechazado, inmutabilidad, anulación y borrado directo rechazado.
- Cancelación bloqueada por cobro emitido y habilitada después de anularlo.
- Nota rechazada fuera de `LISTO_ENTREGA` y documentos persistidos renderizados.
- Concurrencia: dos cobros que superarían el saldo dejan sólo una emisión válida; dos emisiones de nota dejan una única nota.
- Ruff, Django check, `makemigrations --check`, OpenAPI, suite PostgreSQL completa, migración desde base vacía y segunda migración sin cambios.
