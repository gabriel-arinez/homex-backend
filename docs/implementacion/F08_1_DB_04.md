## Alcance implementado

Se incorporó `POST /api/v1/capturas/` para recibir texto asociado a una proforma
en estado `BORRADOR`. La operación exige una `clave_idempotencia` UUID y responde
`202 Accepted` con la captura y el primer intento pendiente.

La autorización se aplica de dos formas:

- el endpoint requiere el rol `VENDEDOR`;
- el vendedor sólo puede crear capturas para sus propias proformas; staff y
  superuser conservan el acceso administrativo previsto por el backend.

El detalle opcional debe pertenecer a la misma proforma.

## Idempotencia T09

`capturas.clave_idempotencia` sigue siendo la restricción única física. El caso
de uso compara además:

- actor;
- proforma;
- detalle opcional;
- SHA-256 exacto del texto UTF-8 recibido.

Un reenvío compatible recupera la captura y el primer intento, sin crear filas
adicionales. Una reutilización incompatible devuelve HTTP 409
`conflicto_idempotencia`.

La creación bloquea la proforma con `SELECT ... FOR UPDATE`. La colisión final
de la clave única se resuelve dentro de un savepoint y vuelve a validar la fila
ganadora. De esta forma dos solicitudes concurrentes convergen en una captura,
un intento y un trabajo outbox.

## Intentos y outbox

`crear_intento` bloquea la captura con `FOR UPDATE`, obtiene el último número e
inserta el siguiente. Django no crea el outbox. El trigger PostgreSQL
`trg_crear_outbox_intento` crea exactamente un `PROCESAR_CAPTURA` después de cada
intento, dentro de la misma transacción.

La relación `TrabajoOutbox.intento` es uno a uno y `clave_unica` también es
única. La clave tiene el formato:

```text
captura:<captura_id>:intento:<numero_intento>
```

Redis y el worker permanecen fuera de esta fase; serán incorporados en F08.2.

## Inmutabilidad T07

La migración `capturas.0005_db04_capturas_outbox_inmutabilidad` reemplaza las
protecciones parciales heredadas por reglas completas:

- un intento cuyo estado previo sea `FINALIZADO` o `ERROR` rechaza cualquier
  `UPDATE` y cualquier `DELETE`;
- `items_ia` rechaza cualquier `UPDATE` y cualquier `DELETE`;
- la validación heredada que sólo permite crear `items_ia` para un intento
  `FINALIZADO` con `resultado_raw` se conserva;
- la reversión de la migración restaura las funciones y triggers anteriores.

La transición que cierra un intento continúa permitida porque la protección
evalúa el estado anterior. Una vez cerrado, input, modelos, relaciones, tiempos,
errores y resultado histórico quedan congelados.
